# 2.0 实现说明

协议 `schema_version=2`，账户 `schema_version=3`。四个主题只是创建参数；客户端没有按篇章分叉的执行脚本。自定义主题直接进入相同生成管线。

## 事实与生成

`StoryBlueprint` 规定目标、角色动机与特长 / 弱点、任务依赖、线索、物品制作配方、转折与收尾条件。初始版本单独保存。开场请求三份候选，按主题、素材覆盖、最近十本特征和结构要求选择，继而生成蓝图及第一页并审校。

`WorldState` 唯一记录位置、认知、归属、资源、关系、任务、承诺与来源。`StoryEvent` 追加保存行动、原因、后果和交互类型；`TurnProposal` 只能提出尚未确认的内容；`BookPage` 保存已验收页面、玩家选择、讨论理由及当时的状态快照。回看读取快照，不重新执行行动。

所有 ID 都是稳定字符串。按钮提交动作 ID；自由表达提交原文，模型返回结构化行动或需要玩家确认的多个理解。不存在 A/B/C 或按关键词打分的归类。否定与歧义保留在原请求中进入审校。新的自由解法可以追加有限的新物品 / 线索 / 可选任务，不能覆盖已有 ID、人物、资源或必要任务。

状态 reducer 检查动作前提、人物在场、道具归属、认知、资源消耗、制作原料、奖励去重、必要任务与承诺、素材有效性及画面对象。关键选择必须有状态后果；同一互动里的替代选择不能产生完全相同的结果。制作原子消耗拥有的原料，重复制造拒绝。任务通过事实条件自动关闭，不靠叙述宣称完成。

新生成蓝图的每项承诺同时包含说明与可验证的事实条件，写入 `promise_conditions`。条件可约束已知线索、实际物品归属或关系，不能循环依赖承诺标志。宣布兑现前，reducer 必须确认所有条件成立；交付承诺需要实际交付条件，不能仅添加“已经送达”的线索。旧作品没有这些字段时保持兼容，不从残缺叙述补造历史。

生成上下文提供世界设定、当前事实、相关事件、最后两页文字 / 选择 / 理由、未完成任务和节奏目标；摘要不能覆盖账本。结构化提案先做程序检查，再独立语义审校；失败最多修订一次并复检。每轮最多四次调用。开场候选、蓝图、第一页及审校共四次，失败可恢复，不接收未经审校的蓝图或第一页。

结局需要任务与承诺完成、设定页数、三种实际互动、两页对先前事件的回应以及角色特长 / 弱点发挥作用。计划页数后最多增加两页；仍未闭合则保存待续。结局图鉴、家庭回顾与新勋章引用同一结局记录及已确认行动证据；四维数值仅保留旧版辅助记录。

## 持久任务与 HTTP

SQLite WAL 使用单 worker；开机将未完成阶段重新排队。单故事同时只接受一个未完成行动。账户 / 幂等键绑定请求摘要，重复请求返回同一任务，复用键但换内容拒绝；状态版本不匹配返回冲突。新状态、页面、事件及完成任务在同一事务提交。提交后响应丢失可以恢复原结果，不重复结算。

| 方法与路径 | 含义 |
|---|---|
| `POST /v2/sessions` | 监护人连接码、同意标志及本地账户秘密换取一小时令牌 |
| `POST /v2/stories` | 主题、角色、年龄、长度、客户端素材能力；返回生成任务 |
| `POST /v2/stories/{id}/actions` | 版本、幂等键、按钮 / 页内操作 / 自由原文 / 理由 / 理解确认 |
| `GET /v2/jobs/{id}` | 规划、生成、审校、完成或失败；包含计量 |
| `POST /v2/jobs/{id}/retry` | 用原任务和原请求重试可恢复失败 |
| `GET /v2/stories/{id}` | 最后确认状态及当前版本待处理任务 |
| `GET /v2/books` | 账户作品列表 |
| `GET /v2/books/{id}` | 同账户作品数据 |
| `DELETE /v2/books/{id}` | 删除同账户作品；有活跃任务时拒绝 |

模型适配支持准确的 OpenAI 兼容 `chat/completions` URL、隔离的 Claude Code CLI 和本地 GLM Coding 接口。`glm-local` 在服务内读取现有 Claude Code 配置，不修改全局设置；真实故事使用同一 GLM 账户的原生 JSON 接口。CLI 传输也已验证，但长规划曾超时；完整评测使用原生接口，见 [接入说明](LOCAL_GLM.md)。只有完整 `finish_reason=stop` 响应可解析；截断、空内容、非结构 JSON、异常审校都不提交。禁止自动重定向；长期模型密钥仅存在服务进程。

模型使用简明意图协议，程序绑定角色 ID、素材、原子操作顺序和请求所需结构。按钮后果已由 reducer 确认，模型不能再次提交同一个行动或追加物品；自由表达必须同时返回理解后的行动和执行后的页面，歧义则保持状态并等待确认。修订保存尚未提交的原草稿，保留已经正确理解的否定和对象。

当前所有权、位置和认知只由当前状态提供，生成上下文去除蓝图中的初始可变字段，避免两份互相矛盾的事实。独立审校使用实际预演后的状态。收束上下文列出必要条件、承诺说明、材料、持有者和交付地点；后段页面须有可执行的推进办法。制作后既可交给在场伙伴，也可放置在当前场景，禁止隔空交付。

页内可先移动，再在另一张卡片于实际到达的地点放置物品。复合动作按物理前提排序：拿起或制作、当前地点的交付、移动、抵达后的交付、承诺验证。所有实际步骤仍由同一 reducer 验证；没有真实移动就不能给远处场景或人物交付。语义审校核对顺序与反馈是否符合玩家所说的办法。

调用发出前先把计量占位写入数据库，随后更新 token / 费用 / 等待时间。服务被终止也不能让已发出的调用从预算中消失。不提供 usage 或费率时费用标为未知；费用限额为正但计量未知时暂停。调用 / token / 费用与模型超时都可配置。

新蓝图和新页面检查不可逆后果：未完成必要任务与承诺所需的物品、制作原料和资源不能被提前耗尽。页内允许先兑现再借回制作；历史账本仍按原规则重放，不改写已确认事件。多个必要配方争用同一只能消耗一次的原料时拒绝蓝图。

客户端采用独立临时文件、同路径读写锁与有限替换重试，修复 Windows 文件短暂占用导致的保存中断。永久失败仍保留旧文件。客户端先原子写入原行动及幂等键，再联网；账户、端点和请求代次共同过滤迟到结果。失败 / 断网保留原请求，恢复后重新查询或重试。客户端账户秘密及短期令牌不等于模型密钥。书架在 `config.savedir/books_v2/` 下按账户分目录（实际路径以客户端 Library 配置为准）。

## 绘本与互动

观察热点、证据排序、物品操作 / 制作、对话协商和资源分配共五类。排序点击卡片，分配通过增减数量操作，道具通过选择原料操作；按钮可使用键盘，无拖拽必需步骤。页内操作先校验并给反馈，确认翻页时批量提交一次。自由表达持续可用。QTE 不属于新故事的固定流程。

观察热点定位在当前物件 / 人物的实际画面区域，侧栏保留点击 / 键盘替代入口。需要物件热点时采用分层画面，试玩、回看和导出使用同一规则。客户端与导出共用规范化画面布局，最多四个人物、六件道具，角色比例由素材清单约束。LLM 只引用素材 ID，坐标由代码决定。关键插图需场景、全部人物、全部道具及本轮事件匹配，否则采用合法分层画面。文字由程序排版，模型文本做显示标签转义，HTML 对文本及 JSON 安全编码。

离线 HTML 自包含字体、WebP / PNG 和完整作品数据，不依赖 CDN 或服务地址。作品选择记录使用实际标签与自由行动描述，结尾显示已确认结局。不同账户的作品不互相出现，回看不改变世界状态。

## 素材与旧数据

120 项已登记资产：18 场景、54 人物、36 道具、12 情境图；其中 6 旧背景沿用，114 新素材来自开发阶段图片生成。90 个人物 / 道具保留真实 alpha 透明背景，最终 WebP 无损编码与源 PNG 的 RGBA 逐像素一致。清单含来源、散列、分辨率、布局比例、适用状态与热点引用。生成提示与参考图片路径在 `assets-source/v2/generations.json`；原 PNG 与废弃候选独立保存于 `raw/`，不打进运行包。

旧账户保留成就、旧图鉴及家庭报告，新增 2.0 字段，不推测旧进行中的世界状态。旧存档仍由旧剧情代码读取。2.0 原生页面从 10001 开始，旧版从 1 开始，防止覆盖；删除账户同时删除其两组原生页。JSON 作品另行隔离保存。旧版包保留以便退回。

## 已知发布边界

本实现适用于单实例受控桌面服务。没有支付、运行时生图、多端账户同步和跨世界冒险。真实模型生成能力与趣味性须按 60 本 / 20 组标准检验，不能从模拟服务通过推导。三平台已完成原生安装包自动化测试，真实 GLM 已接入；按用户决定，人工逐本检查和盲评仍待执行，正式发布门禁保持关闭。Mac 包未签名、公证；套餐账单金额未知。
