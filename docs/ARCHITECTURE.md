# 架构说明

## 质量目标

1. 没有网络也能从新建账户完整玩到结局。
2. 一次玩家选择只产生一次故事提交、一次属性结算和一次统计写入。
3. 账户数据、手动存档和私有快存互不串号。
4. 远端服务、系统自读和本地存档各自有清晰的数据边界。
5. 儿童可以用触屏、鼠标或键盘完成所有关键交互。

## 运行链路

```text
账户选择
  → 角色与冒险设置
  → StoryGame 初始化
  → 本地故事 / 显式选择的受控云端故事
  → 完整响应校验
  → 分段渲染与一次性属性结算
  → 本地评价和家庭共读记录
  → 按 run_id 幂等写入当前账户
```

`game/story_service.rpy` 是唯一故事服务边界。它负责输入清理、端点校验、严格 TLS、响应尺寸上限、流完成校验和离线回退。`game/script.rpy` 负责领域模型与解析，`game/flow.rpy` 负责主流程，`game/account_system.rpy` 负责账户与存档命名空间。

## 状态约束

- `_request_epoch` 标识当前生成；旧线程不能提交到新一局。
- 响应必须完整解析后才一次性进入渲染队列，半截故事不可存档。
- `story_state_is_stable()` 为假时禁用存读档。
- `run_id` 防止结局、统计、勋章和家庭记录被重复写入。
- 回滚和全局自动存档关闭，避免外部状态与 Ren'Py 回滚状态分叉。

## 数据边界

- `persistent.accounts[account_key]` 保存当前账户的图鉴、勋章、统计与家庭记录。
- 每个账户占四个存档页；第四页第 12 位是该账户私有快存。
- `.local/` 只保存开发机运行数据。
- `archive/` 保存历史风险样本，构建规则明确排除。
