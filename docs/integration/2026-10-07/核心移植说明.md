# Linux 故事核心移植

已在当前工作目录完成选择性移植。源为 Linux `m3-r2@85140750c5e2d2ee5760af158dd9ffd1b9b000e8`，采用其 LeanWriter 写作方向和内容素材，适配现有 Ren’Py 游戏；没有合入整套新版 Session、书库和媒体系统。

## 立即体验

双击项目根目录的 `启动游戏.command`，选角后在冒险设置中开启「云端动态故事」，再点情景旁的「随机」。也可以直接写自己的情景。

启动器使用智谱普通按量 API，默认 `glm-5.3`，high 思考。凭据只从已有本机配置读取；游戏进程获得的是随机本机代理令牌。旧的 `dist/1.1.0-rc.1/` 包尚未重打，请从工作目录启动。

## 改了什么

| 部分 | 结果 |
| --- | --- |
| 写作 | 提取精简写作原则、九位角色的性格/声口/外观、42 张奇遇卡、两个节奏示例。去掉云端强制教学题和感官描写配额。 |
| 续写 | 保留完整前文和已选行动；每轮注明剩余进度、当前属性和需要首先兑现的行动后果；旧在线存档继续时也采用新提示。 |
| 格式 | 生成三小页 JSON，转为原有场景、旁白、角色对话和选项。接受紧凑或排版后的 JSON；选项编号由本地分配。 |
| 失败恢复 | 截断、空正文、缺选项、提前剧终不会进入剧情历史。格式问题最多修正一次；失败后停在当前选择，手动重试不重开故事、不重复计数、不接入其他本地篇章。 |
| 结算 | 只有有效结局才结束；重复属性标签按整轮合并并限制在 ±2。评价/报告使用完整剧情；云端评价失败时从实际末幕整理回顾。 |
| 运行边界 | 界面、账户、选角、离线篇章及存档数据结构保留。存档沿用 `.local/player-saves`；启动器新增临时文件和签名数据也留在工作目录。 |

主要实现：`game/story_writing.rpy`、`game/story_content/lean.json`、`game/story_service.rpy`，以及原 `StoryGame` 和错误重试流程的局部修改。没有更换背景资源，没有加入 AI 插画或配音。

## 已验证

- 纯 Python：原有 576 条离线路径通过；新增 10 项联网边界回归通过，包括原选择重试、失败末轮恢复、JSON 转换、格式修正上限、截断拒绝、重复属性标签、评价历史和旧状态恢复。
- Ren’Py 8.5.2：lint 无诊断；真实引擎的 216 组离线组合及故障/恢复检查通过。
- 实际界面：开场失败重试、三个选择、保存、末轮失败重试、结局和一次性入账通过，11 个断言；截图位于 `ui-proof/`。测试点击需等待场景稳定，已排除过早点击导致的测试超时。验证了保存及状态恢复，未遍历用户的全部历史存档。
- 普通按量 API：两条真实故事完成，共 10 段。其一走五次选项，其二走三次行动，包含“和自己的影子交换工作一天”的自由输入。单轮等待中位数 10.3 秒，范围 7.3–23.74 秒，包含自动修正等待。

验收并非一次全通过：初稿存在无声设定仍说话、打闹过重、篇幅过长等问题；据此补充了角色/写作约束，并采用逐页 JSON。最后连续试玩的第二个开场仍出现选项格式失败，修正 JSON/编号兼容后，单独复跑该故事至结局通过。原始失败记录保留在 `live-stories.json`，成功复跑在 `live-shadow.json`；没有把失败改记为成功。

试玩全文：[真实试玩.md](./真实试玩.md)。验证摘要：[verification.json](./verification.json)。代码回归日志：`core.log`、`unit.log`、`engine.log`、`ui.log`、`lint.log`。

这些样本证明生成、选择、自由输入和恢复链路已接通，不能保证每一局文学质量或语义一致性。样本仍有物件来历、规则解释略跳跃的地方。本次优先消除了程序直接换剧情的断裂，并让新写法可在现有游戏里体验；尚无严格的人类盲评结论。
