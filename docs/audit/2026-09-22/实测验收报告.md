## 确定性问题与修复建议

### P1：属性弹窗约 1.6 秒后变透明，游戏仍被模态遮罩拦住

复现：完成任意一轮选择，推进到“属性变化”弹窗，不立即点击“知道了”，等待超过 2 秒。弹窗及按钮消失，背景仍变暗，普通空格推进不能进入下一轮。主流程停在 `call screen stats_change_popup`。此现象在多轮实际试玩中重复出现。

原因：`stat_change_center_popup` 的动画在 0.2 + 0.1 + 0.8 + 0.5 秒后将整个 frame 的 alpha 设为 0；`stats_change_popup` 仍是 `modal True`，没有自动 Return。新增的确认按钮也在同一个透明 frame 内。

- [模态弹窗和确认按钮](/Users/vvcc/Downloads/熊出没奇遇/熊出没奇遇/game/game_screens.rpy:1076)
- [刚出现的弹窗](/Users/vvcc/Downloads/熊出没奇遇/熊出没奇遇/docs/audit/2026-09-22/07-popup-visible.png)、[消失后仍被拦住](/Users/vvcc/Downloads/熊出没奇遇/熊出没奇遇/docs/audit/2026-09-22/08-popup-invisible-block.png)、[空格推进仍无效](/Users/vvcc/Downloads/熊出没奇遇/熊出没奇遇/docs/audit/2026-09-22/09-space-cannot-continue.png)

本次用方向键聚焦隐藏按钮再按 Enter 才继续。这是诊断时的绕过手段，不能作为儿童正常玩法。建议保留提示及按钮直到确认，或在动画结束时真正关闭整个 screen。修复后必须加入等待超过 2 秒再继续的界面回归。

### P1：发行包遗漏必需音乐，原有构建门禁误报通过

重新使用正式归档方式构建了 PC 和 macOS 包。两者只有 `archive.rpa`，均没有 `audio.rpa`；展开 ZIP 并读取 RPA 索引，确认 `audio/music.mp3` 不在任何位置。

对新 macOS 包运行 Ren’Py lint，得到明确错误：

```text
game/flow.rpy:17 'audio/music.mp3' is not loadable
```

原因：[音频分类配置](/Users/vvcc/Downloads/熊出没奇遇/熊出没奇遇/game/options.rpy:229)将音乐分配到 `audio`，但项目没有调用 `build.archive("audio", "all")` 声明该归档。主菜单与主线又都引用这首音乐。发行包能打开菜单，不等于资源齐全。

建议声明音频归档或并入已有 `archive`；然后检查最终 ZIP/RPA 的必需资源清单、运行产物 lint，并实际播放验证。当前 [构建检查](/Users/vvcc/Downloads/熊出没奇遇/熊出没奇遇/tools/run_build_verify.sh:25)主要检查脚本存在和风险目录，没有验证音乐，因此本次仍报通过。

### P2：本地模式下，多项设置没有兑现对应玩法

本地引擎的中间章节是四个固定模板，按轮次取模循环。选择会改变反馈句及属性，但不产生不同场景路线。情景主题会出现在开场，后面的章节任务不会随主题变化。实际选择“森林运动会”，后续仍是清理河道、树洞图案、山顶路线和拼线索。

通过真实引擎内的对照调用确认：在同一角色、同一轮、同一选择下，分别改变主题、亲子模式、难度、问题提示神器及命运文本，中间章节输出完全相同。模式、难度和神器参数主要进入云端 prompt；本地故事并未实现相应变化。难度会影响 QTE 目标，但本地故事生成器不产生 QTE，所以不能据此把本地难度选项判为有效。

- [固定章节生成](/Users/vvcc/Downloads/熊出没奇遇/熊出没奇遇/game/story_service.rpy:195)
- [对照试验结果](/Users/vvcc/Downloads/熊出没奇遇/熊出没奇遇/docs/audit/2026-09-22/extended-logic.json)

建议在当前离线版本明确限制或隐藏尚未实现的设置，或补齐本地对应逻辑。所谓 5/10/15/20 分钟在实现中映射为 3/5/7/10 轮，没有保证实际阅读时间；较长局会重复四个章节。

### P2：指定结局与结局档案类型不一致

把结局指定为“留白式结局”，本地结尾确实出现开放式收束，但评价模板仍写死“结局类型：温馨成长”。`extract_ending_info` 据此生成档案，所以保存下来的结局分类丢失了玩家选择。

- [结尾按设置生成](/Users/vvcc/Downloads/熊出没奇遇/熊出没奇遇/game/story_service.rpy:178)
- [评价中写死的类型](/Users/vvcc/Downloads/熊出没奇遇/熊出没奇遇/game/story_service.rpy:250)

建议让评价与档案读取同一份实际结局数据，而不是从固定文本重新推断。

### 其他已观察到的问题

- 读档和退出确认主体仍是英文，与中文儿童界面不一致。
- 设置页“本地故事”后的勾号显示为缺字方框；家庭报告直接显示 `**标题**`，没有使用与评价页一致的 Markdown 转换。
- 长输入框旁的控件存在布局问题：设置页“随机”按钮没有出现在可见区域，自定义行动“确定”按钮位于内容框外侧。
- 主菜单中完成账户切换后直接进入开场，而非回到主菜单；应确认是否符合预期交互。
- macOS 包的 Bundle Identifier 仍为 `com.domain.game`，版本仍带 `alpha` 标识；尚不是完整的发行配置。

以上不扩大为所有设备上的结论。界面截图是在本机真实窗口尺寸下采集，部分尺寸在测试过程中发生变化，不能替代固定分辨率矩阵。

## 为什么旧检查全部通过仍不足以发布

[原有视觉用例](/Users/vvcc/Downloads/熊出没奇遇/熊出没奇遇/tools/qa_visual.rpy:14)只打开四个 screen、等待 0.5 秒、保存截图，然后退出。它没有覆盖属性弹窗，更没有验证超时后的按钮可用性、完整通关、报告入库或多账户切换。其运行报告显示 1 个 testcase、0 个测试 DSL assertions。

原有逻辑回归只覆盖 3 组纯 Python 函数。它们通过能说明部分逻辑可靠，不能排除 Screen Language、动画、文件分类和实际资源加载问题。原有构建检查没有启动最终发行包，也没有对最终资源逐项断言。本次对产物再运行 lint 才发现音乐缺失；该 lint 命令虽然进程退出码为 0，报告正文仍包含缺资源发现，门禁应解析结果或使用资源断言，不能只看退出码。

补充测试在真实 Ren’Py 运行时调用原代码：216 组离线逻辑用例覆盖终止轮次、选项数量、属性上下界及评分一致性；传输替身覆盖六种故障回退。它们没有验证真实网络延迟、真实服务审核或 Windows/Android 的 UI 行为。
