## 2. 旧版当前如何运行

```text
账户 → 选角与设置 → StoryGame → 故事服务 → 标签解析 → Ren’Py 对话与交互
                                      │
                     ┌────────────────┴────────────────┐
                     │                                 │
             默认本地模板                    显式启用云端 + 配置端点
             四篇手写篇章                       messages 全历史请求
                     ↑                                 │
                     └────────── 云端故障回退 ──────────┘
```

- `game/flow.rpy`：主要游戏循环，调用 `start_stream` / `continue_story_stream`。
- `game/script.rpy`：角色、提示词、`StoryGame`、标签解析、渲染、评分和报告，约 1830 行。
- `game/story_service.rpy`：网络和回退边界。
- `game/local_adventures.rpy`：四个有限篇章；第一轮选择分路，随后主要按轮次选固定事件。
- `game/game_screens.rpy`、`screens.rpy`、`account_system.rpy`：交互界面、菜单、账户与存档。
- 未提交的 `tools/run_glm_game.py`：本机代理。它继承本机模型配置，向上游发非流式请求，收到完整结果后包装成一个 SSE 事件。

**代码里并没有漏传整个历史。** `StoryGame.messages` 保留了系统提示、玩家输入和历次生成，下一轮全部重发。但当前属性、家庭讨论、实际渲染时丢弃的内容、是否发生本地回退等，没有统一转化为模型可依赖的剧情状态。故事本身也没有可回访的节点树；重新开始或读取旧存档不等于持久化世界线探索。

“实时”目前主要是每次选择后重新生成。代理与客户端均等待完整回复，才开始逐段显示；网络期间不能先阅读已经完成的页面。背景是六个固定场景，不是按故事实时生成的插图。

## 3. 痛点的代码根因与复现

### 3.1 关联性断裂：故障回退改变故事事实（高优先级）

用真实函数和假超时传输复现：场景是“月亮列车”，玩家刚选择 **“C. 请光头强一起爬上树”**。回退内容却变成：

> 你决定“请伙伴回忆刚才的路标”。每位伙伴都分到了适合的任务，大家一起完成了这一步。

随后进入光头强家及旧工具箱情节。原因是本地引擎把云端选项的 C 映射为本地该轮的 C；它并不理解此前的云端剧情。

`online_enabled` 此后仍为真，模板文本又被存为 assistant 历史，所以下一轮会继续调用云端，并让模型接续已经被替换的故事。通知称“切换到本地模式”，实际只是当轮回退。

证据：[复现结果](/Users/vvcc/Desktop/XiongchumoQiyu/docs/audit/2026-10-07/evidence/legacy-probes.json)，源码 `story_service.rpy:258`、`local_adventures.rpy:165`、`script.rpy:1354`。合并后的恢复策略应保留当前世界线，重试、续写或返回书架；不要用无关篇章续接。

### 3.2 语言僵化：同一模板和约束被不断重复

本地儿童模式每轮写固定台词“先看看眼前的线索，再选一个办法试试吧”；观察、行动、合作只有三句固定反馈。中段选择很少改变事件路径，自由输入也被关键词归类。

云端提示要求每段至少两种感官细节、颜色和拟声词、定期知识题、每轮属性标签、短选项、既定角色口头禅等；系统提示结尾每次仍要求“开始创造故事”“开场场景”。这会给模型很强的重复写法。收尾主要靠最后两轮追加指令，达到轮数便设置结束状态，缺少对故事是否已经自然收束的判断。

这些是生成结构的限制；本次没有重新抽样旧版在线故事，不把代码推断冒充新的真实模型质量结论。历史报告关于个别存档实际使用本地模式的判断，也不代表用户每次体验都处于本地模式。

### 3.3 仍存在的可靠性问题

| 问题 | 本次证据 | 影响 / 边界 |
|---|---|---|
| 客户端接受 `finish_reason=length` | 假响应下，非流式和 SSE 均接受半截句子；SSE 只要有 `[DONE]` 即可 | 通用端点路径可能显示截断故事；当前 GLM 代理另外检查 `stop`，走该代理时会转为回退问题 |
| 响应完整性校验过弱 | 只有一个场景标签也能通过提交，无正文、无选项、无回退提示 | 玩家可能面对空推进或异常自由输入；“可解析”不足以代表可玩 |
| 同轮多个属性标签累计 | 两个 `智+2` 使智慧从 5 到 9 | ±2 限制按标签执行，没有按回合去重或统一结算；不是每个正常回复都会触发 |
| 服务诊断日志可能不落盘 | 源码使用 `renpy.log`，工程未设置 `config.log`；本机 SDK 的该函数在未设置时直接返回 | 主运行日志存在，不代表请求失败原因也被记录；排障缺乏可观测性 |
| 评价并非完整上下文 | 异步评价 / 报告只取最后 10 条记录，生成文本每条截 500 字，却仍称“完整对话记录” | 长局的早期选择可能不进入评价依据 |

复跑：[probe_legacy.py](/Users/vvcc/Desktop/XiongchumoQiyu/docs/audit/2026-10-07/probe_legacy.py)。它只提取当前源码中的 Python 定义，网络由内存替身替代，不读写玩家存档。

## 4. Linux 改进的价值及目前的边界

新版使用独立的纯 Python 包 `game/xcmengine`，界面预期只调用 `Session` 并读取快照。

| 层 | 已有实现 | 对本需求的价值 |
|---|---|---|
| 数据 | `Book / Node / Page / Option / Ending`，JSON 持久化 | 书和分支可保存、重读、返回岔路，选择具有稳定身份 |
| 生成 | JSON 对象增量解析、逐章生成、断流续写、修复、取消、计量 | 已完成页面可先提交，出错保留已提交内容 |
| 内容 | 角色声口、美术描述、奇遇卡、示例、词句约束、历史使用记忆 | 让变化有素材来源，减少同一本及多本间机械重复 |
| 会话 | 当前阅读位置、分支预生成、选择后提升任务优先级、页面版本 | 支持边读边准备下一步，避免过期图片覆盖新页面 |
| 媒体 | 插图提示、图像客户端、逐句朗读、缓存及占位背景 | 为绘本画面和朗读建立接口；尚不能证明实际全链路延迟达标 |

## 5. 真正的合并阻塞与已验证补丁

`git merge-tree` 对 `0071ef8` 与 `8514075` 的预演**无文本冲突**，合并树为 `7524d4a…`。但是自动合并后的原有测试全部通过，仍漏掉两个兼容问题：

1. **长页拆分后，阅读出口和结局位置错误。** Writer 将过长的一页拆为两页，Session 却仍读取固定的 `book.chapter_sizes()`。复现中一章实际有 4 页，第 3 页已标为岔路口，第 4 页既没有下一页也没有岔路出口。结局章实际有 5 页，却在第 4 页标记已读结局，真正末页没有结局出口。按计划中的 UI 路由接入会卡住。

这些风险及候选修法原先已记在 Linux 第三轮日志和仓库外的审查目录，但未进入 `rewrite/session.py`。本次使用其跨模块用例在当前合并快照重新验证，三个相关用例全部失败。

已保存 [session-compat.patch](/Users/vvcc/Desktop/XiongchumoQiyu/docs/audit/2026-10-07/session-compat.patch)，只在隔离合并副本应用并验证：

**补丁不是完整合并。** 它以两分支合并后的代码为前提，不能单独打到旧 Ren’Py 原型上。跨模块用例一并保留于本目录 `contract/`，应在后续整合时加入新版常规测试。

3. **补齐 Ren’Py 界面。** 当前两个实现分支均没有 `.rpy` 文件；计划中的 `xcm_*` 界面、桥接、路由、字体接入、游戏配置尚未落地。需要完整接通选书、开书、阅读、岔路、自由点子、结局、地图、书架和错误恢复。精简生成器的 `rule/refrain` 可能为空，开书动画应按实际字段呈现。

5. **针对最终代码验收。** 先完成当前正式 LeanWriter 的文本评测；再测真实 Session 的图文音频时间线、拆页、返回分支、重启续读、断网、账户错误和预算。最后在实际 Ren’Py 阅读界面验证字体、卡片溢出、键鼠交互、声音、发布资源及启动器。现有大量测试不能替代这些环节。
