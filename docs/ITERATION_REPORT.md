# 质量迭代记录

## 第一轮结论

主风险并不只是“目录有些乱”，而是发布边界、故事生成边界和玩家状态边界彼此混在一起。历史发行包携带过客户端凭据，在线故事允许证书校验降级；本地流程又依赖在线成功，因此断网会直接破坏核心体验。多账户数据与全局快存混用，流式生成也可能在半截状态下写入或被旧线程污染。

## 已执行的 P0/P1 改进

- 清除源码中的客户端密钥和 TLS 降级路径，旧编译物与旧发行包进入隔离区。
- 新增完整离线故事引擎，联网改为显式选择、环境配置、严格 HTTPS 和失败回退。
- 用 generation epoch 阻断旧请求提交，先完整校验响应再一次性进入队列。
- 统一剧情渲染路径，修正场景识别、选项解析、属性上限、QTE 结算和评分一致性。
- 以 `run_id` 幂等写入统计、结局、勋章与家庭共读记录。
- 修复多账户迁移、损坏数据修复、账户私有快存、页码边界和切换入口。
- 关闭与外部生成状态冲突的回滚和全局自动存档，并在不稳定状态禁用存读档。
- 补齐六张真实 WebP 背景，隔离候选图与棋盘格占位图。
- 统一为森林、蜂蜜、树皮与羊皮纸色系，调整字体、触控目标、长列表滚动、QTE 键盘与辅助完成。
- 网络语音依赖改为系统自读，脆弱和高风险的 vendored Python 依赖移出运行目录。
- 引入 Ren'Py 8.5.2 固定版本的 lint、核心逻辑回归、界面截图回归和 PC 临时发行包审计。

## 2026-08-23 验证快照

- 项目扫描通过：11 个 Ren'Py 源文件、6 张唯一正式背景，无高风险残留。
- 核心逻辑的解析、离线引擎和账户修复回归全部通过。
- Ren'Py lint 通过：24 个图像声明、50 个屏幕，零发现。
- 自动化界面用例通过：2 个套件、1 个用例，并人工复核 4 张关键界面截图。
- PC 临时包通过：1547 个文件、ZIP 81 MiB，无项目源码或风险目录混入。

## 后续优先级

P1 是撤销并轮换历史凭据、三平台实机冒烟、Android 最小权限和全部资产授权确认。P2 是增加更多离线章节变化、为百科热点增加更明确的焦点态，并以真实儿童/监护人可用性测试校准 QTE 与阅读速度。
